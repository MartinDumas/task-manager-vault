# Валідація булевих значень параметра limit

## Контекст
`VaultConnector.search_notes(query, limit=10)` приймає `limit` для обмеження кількості результатів. У `mcp_connector/core.py` перевірка типу зараз використовує `isinstance(limit, int)` та обмежує значення діапазоном 1–30. У Python `bool` є підкласом `int`, тому `isinstance(True, int) == True` і `isinstance(False, int) == True`.

## Проблема
Поточна перевірка приймає `limit=True` як число `1` (і так само `False` як `0`, яке відхиляється вже перевіркою діапазону). Отже, булеве значення `True`, яке навряд чи є навмисним лімітом кількості результатів, непомітно змінює запит до одного результату замість явної помилки валідації.

## Запропоноване рішення
У майбутній зміні явно відхиляти значення типу `bool` для `limit`, перш ніж приймати цілі числа в діапазоні 1–30. Зберегти прийнятні значення `int` та існуючу перевірку діапазону. У цьому ADR рішення має статус `proposed`; продуктивний код цим записом не змінюється.

## Альтернативи
- Залишити загальну перевірку `isinstance(limit, int)` — відхилено як цільову поведінку: Python вважатиме `True` цілим числом і валідація пропустить його.
- Перевіряти `type(limit) is int` — технічно виключає `bool`, але змінює правило приймання всіх підкласів `int`; окрема перевірка `isinstance(limit, bool)` перед перевіркою `int` точніше виражає намір.
- Перетворювати bool на число або трактувати його як відсутній ліміт — відхилено, бо це приховує помилковий аргумент замість чіткого повідомлення про валідацію.

## Наслідки
`True` і `False` будуть явно відхилятися як некоректні значення `limit`; цілі числа від 1 до 30 залишаться допустимими, значення поза межами — відхилятимуться. Тести мають закріпити відхилення обох булевих значень і зберегти перевірки меж та коректних цілих значень. Це узгодить типове очікування від ліміту з фактичною валідацією та зробить помилку виклику видимою.

## Наслідки та ризики
Якщо якийсь наявний виклик навмисно використовував `True` як скорочення для ліміту 1, він отримає помилку після майбутнього виправлення; такий виклик потрібно буде замінити на `1`. Є ризик непомітно не додати регресійні тести на `bool`, тому зміна має супроводжуватися тестами для `True`, `False`, допустимих цілих і меж 1 та 30. Сам ADR не змінює реалізацію.

## Підстава та пов'язані нотатки
Реалізація `search_notes` в `mcp_connector/core.py` містить умову `not isinstance(limit, int) or not (1 <= limit <= 30)`, через яку `True` наразі проходить як `1`. `TestSuite` задає контекст автоматизованого тестування; наявний ADR про ізоляцію тестів MCP-конектора описує відокремлене тестове середовище, але не цю валідаційну поведінку. Пошук нотаток за назвою рішення та термінами `search_notes`, `limit`, `bool` не виявив дубліката.
